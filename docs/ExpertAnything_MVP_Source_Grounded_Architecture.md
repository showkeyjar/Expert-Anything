# ExpertAnything MVP：来源约束架构

## 核心修正

系统不能把“上传成功”当成“已经理解”，也不能把关键词抽取当成知识建模完成。

MVP 的可信链路必须是：

```text
原始资产
  -> 格式解析
  -> 原文保存与可读展示
  -> 带证据的概念候选
  -> 带证据的关系候选
  -> 基于证据的学习动作
  -> 用户练习与反馈
```

## 当前实现边界

- `source_text` 是每个资产的原文基础记录。
- `Concept.evidence` 保存概念对应的原文片段。
- 关系只使用同一句原文中的 `co_occurs`，不能宣称因果、依赖或先后关系。
- Teacher Agent 只返回原文证据和阅读提示，不声称完成了超出证据的理解。
- 没有证据的概念不能生成解释。
- Reviewer Agent 评估的是用户对证据的回忆和应用，不是系统自身的“理解分数”。

## 后续升级顺序

1. 引入页码、章节、段落等稳定的 `SourceLocation`。
2. 使用结构化抽取器生成概念、命题和关系，并要求每条结果携带来源定位。
3. 接入 LLM 时采用“检索证据 -> 生成回答 -> 引用校验”的流程。
4. 只有通过来源校验的内容才能进入知识图谱和学习路径。

## Teaching Room

教学会话是 MVP 的主交互，而不是“分析、原文、练习”几个工具页的拼接。

- Align：Tutor Agent 先询问学习目标、已有基础和偏好的理解方式。
- Teach：根据 Learner Model 选择当前概念，组合原文依据、知识脉络、例子和视觉步骤。
- Respond：用户用自己的话回应，系统记录掌握度和回答。
- Adapt：Tutor Agent 根据反馈选择下一个教学单元。

分析页、原文页和练习记录是辅助视图，不能替代教学会话本身。
